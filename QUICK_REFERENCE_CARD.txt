# H Matrix Per-Sequence Variation - Quick Reference Card

## What You Asked For
"Add an option that the real H will not be the same for all sequences, I want it to change in up to 0.3 radians"

## What Was Implemented ✅

Each training/validation/test sequence now gets a **randomly rotated observation matrix H** within ±0.3 radians.

---

## Current Configuration (Already Set)

**File:** main_lor_DT.py, line 106
```python
DataGen(..., H_vary_per_seq=True, H_max_rotation_rad=0.3)
```

**Result:**
- ✅ Feature ENABLED

- ✅ Rotation range: ±0.3 radians (≈ ±17.2°)


---

## How It Works (Simple Version)

1. For each sequence during data generation
2. Generate random rotation angle: θ ∈ [-0.3, +0.3] radians
3. Rotate H matrix: H_new = rotate(H_original, θ)
4. Generate measurements with rotated H: y = H_new @ x + noise
5. Store measurements (with varied H built-in)

## Common Questions

**Q: Will this break existing code?**
A: No. New parameters default to original behavior (H_vary_per_seq=False).

**Q: Do I need to change anything else?**
A: No. It's already enabled in main_lor_DT.py. Just run your script.

**Q: Can I turn it off?**
A: Yes. Change H_vary_per_seq=False in DataGen call.

**Q: How much faster/slower is training?**
A: No difference - rotation happens during data generation (once), not during training (each epoch).

**Q: Will saved data be different?**
A: Yes - saved measurements will include H variations. Old saved data won't have them.

**Q: Can I use 0.3 for training and different for testing?**
A: Yes. Make separate DataGen calls with different H_max_rotation_rad values.
